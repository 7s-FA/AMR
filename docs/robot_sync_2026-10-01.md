# 실제 로봇 변경분 동기화 — 2026-10-01

Burger1/M1, Burger2/M2의 현재 로봇 내부 코드를 PC 작업 사본에 가져오고, 기존 AMR 파일 구조에 변경분을 병합했습니다. 로봇에 파일을 쓰거나 서비스를 재시작하거나 주행 명령을 보내지 않았습니다.

## 반영 순서와 원본 보존

1. PC의 기존 로봇별 소스를 먼저 백업했습니다.
2. SSH로 실제 로봇 소스를 읽어 원본 스냅샷과 파일별 SHA-256을 저장했습니다.
3. PC의 `final_robot_ws/robot/burger1`, `robot/burger2`를 갱신했습니다. 변경 35개·추가 70개이며, 추가 파일에는 로봇에 있던 과거 `.before` 백업도 포함됩니다. Burger1 README의 PC 운용 주석은 유지했습니다.
4. AMR에는 실행에 필요한 변경·추가 파일만 반영했습니다. 기존 PC 원본, 새 로봇 원본, AMR의 기존 수정본을 비교해 Action 연동·정지/속도 게이트와 경로 구성을 보존했습니다.
5. 사용자 요청에 따라 일반 도킹은 최신 Burger1 제어 로직을 공통으로 사용하도록 정리했습니다. PC 작업 사본의 Burger2 제어 파일·설정에도 같은 변경을 적용했습니다. **따라서 이 두 파일은 로봇에서 읽은 원본보다 한 단계 더 수정된 작업본**입니다. 원본은 스냅샷에 남아 있습니다.

PC 백업·상세 비교 기록:

```text
/home/jh/final_robot_ws/output/robot_to_amr_sync_20261001_150617/
├── pc_before.tar.gz                    # 갱신 전 PC 사본
├── pc_before_hashes.json
├── shared_before_hashes.json           # 보호한 최상위 공용 host_ws/src
├── burger1/remote_before.tar.gz         # 로봇 원본
├── burger2/remote_before.tar.gz
├── pc_sync_report.json                 # PC에 가져온 변경
├── pc_user_requested_adaptations.json   # 일반 도킹 공통화 2개 파일
└── amr_merge_report.json                # 변경분 병합과 새 의존 파일 매핑
```

최상위 공용 `final_robot_ws/host_ws/src`와 Git 저장소의 F1/M3 영역은 변경하지 않았습니다. `.before` 백업·생성된 DDS XML·외부 카메라 소스 전체는 AMR에 추가하지 않았습니다. `restore_camera.sh`는 로봇의 과거 소스/펌웨어 백업에 의존하므로 PC 스냅샷에만 보존합니다.

## 주요 변경

| 범위 | 반영 내용 |
|---|---|
| 공통 준비 | AMCL 초기 위치를 서비스 응답으로 확인, ROS 환경 캐시, 준비 상태 모니터 |
| 카메라·도킹 시작 | 대기 촬영 2fps, 도킹 시 M1 20fps/M2 15fps 복원, 대기 상태 비전 준비와 명시적 도킹 요청 |
| 일반 도킹 | `common/runtime/docking_control.py` 단일 제어 코드. 두 프로필의 일반 `control` 값 동일 |
| 일반 도킹 보정 | 보드 법선 추종, yaw 오차에 따른 회전 속도 제한, 회전 가속 제한, 0.6 회전 배율, 전진 0.039m/s |
| 주차 | 두 프로필 모두 새 일반 도킹 보정 옵션을 끄고 기존 주차 속도 유지. M1 0.039m/s·0.234rad/s, M2 0.0468m/s·0.2808rad/s |
| M1 카메라 | 기존 전용 캡처에서 M2와 같은 camera_ros 방식으로 변경. 640×480 프로필과 로봇에서 읽은 보정값 반영 |
| 두 로봇 경로 | way3의 y를 기존보다 -0.03m 이동. rest는 way4로 바로 이동. M2 park는 way4 → 주차 도킹 유지 |
| 주행 튜닝 | 전진 위치 추종 속도 0.06336m/s, 종단 접근 0.024m/s, 로봇별 회전·가감속 설정 반영 |
| M1 주행 차이 | 구간 시작 방향 차이 100도 초과 시 선회, 중간 지점 yaw 정렬 생략. 최종 방향 검증 유지 |
| M2 주행 차이 | 구간 시작 방향 차이 35도 초과 시 선회, rosbag을 끈 경우 가벼운 motion_state.jsonl 기록 |

일반 도킹 공통화는 **PC 작업 사본과 AMR에 적용**했습니다. 실제 Burger2 내부 파일은 변경하지 않았으므로, 현장에서도 동일한 일반 도킹을 쓰려면 검토한 작업본을 별도로 배포해야 합니다. 로봇별 주차 마커·좌표·namespace·카메라 실행 설정은 유지합니다.

기존 `Burger.action`, `/m1/data`·`/m2/data`, RESTART의 정지 해제 의미, Action 정지 래치·heartbeat·속도 출력 상한은 유지했습니다. Action 프로필의 최대속도 설정도 이번 주행 파라미터 이관만으로 임의로 올리지 않았습니다.

## 검증

| 검사 | 결과 |
|---|---|
| M1 / M2 구성 각각 host_pkg + amr_mission + waffle_navigation 빌드 | 모두 통과 |
| Action 계약·Backend·패키징·공통 일반 도킹 동작 | 42개 통과 |
| 격리된 ROS Action 통신 | 5개 통과 |
| M1 Nav2 회귀 검사 | 197개 통과 |
| M2 Nav2 회귀 검사 | 182개 통과 |
| M1 도킹·카메라·모의 ROS 노드 검사 | 70개 통과 |
| M2 도킹·모의 ROS 노드 검사 | 60개 통과 |

총 **556개**가 통과했습니다. Python/Bash 157개 파일의 문법도 확인했습니다. 카메라 입력 형식·주행 속도·방향 정렬 정책에 대한 오래된 테스트 기대값은 현재 가져온 구현에 맞춰 갱신했습니다. 새로운 일반 도킹 검사는 두 프로필에 동일한 센서 입력을 넣어 출력 일치, 센서 지연 시 정지, 기존 주차 한도를 검사합니다.

ROS 통신 검사는 localhost와 테스트 도메인으로 분리했습니다. Action은 232, 동시에 실행한 도킹 노드 검사는 M1 231/M2 232를 사용하여 시험용 토픽끼리 충돌하지 않게 했습니다. 실제 운영 도메인은 계속 40입니다. Action 테스트 종료 시 rclpy의 Destroyable 정리 경고가 출력되었으나 5개 검사는 통과했습니다.

실제 로봇 주행·도킹·GPIO·새 M2 일반 도킹 튜닝은 이번 동기화에서 시험하지 않았습니다. 기존 본체 드라이버 종료 코드 -6 문제를 해결한 작업으로 해석하면 안 됩니다.
