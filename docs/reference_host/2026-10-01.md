아래 경로는 지정 호스트의 `src/host_pkg/src` 아래입니다.

| 위치 | 현재 동작 | 영향 |
|---|---|---|
| `control.py:64` | 존재하지 않는 `shared_memory.burger1_message` 참조. 실제 정의는 `burger1_end_message` | M1 성공 후 AttributeError로 다음 단계 진행 불가 |

호스트 소스는 소유 담당자가 처리할 수 있도록 그대로 남겼습니다. 로봇이 가짜 완료를 반환하거나 예전 명령을 임의로 허용해 우회하지 않았습니다.

## 현재 개별 시험

본 호스트의 전체 공정은 위 문제 때문에 정상 동작을 보장할 수 없습니다. 준비된 로봇의 개별 주행은 AMR의 별도 테스트 호스트로 요청할 수 있습니다. 로봇에는 **이번 AMR 런타임을 배포·빌드**한 다음, 로봇 터미널에서:

```bash
# docs/commands.md의 AMR_RUNTIME 및 amr 함수 설정 이후
amr mode process
amr ready
amr action
```

호스트 PC의 다른 터미널에서:

```bash
cd ~/AMR
bash tools/test_host/build.sh     # 최초 한 번
export ROS_DOMAIN_ID=40
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
unset ROS_LOCALHOST_ONLY ROS_AUTOMATIC_DISCOVERY_RANGE ROS_DISCOVERY_SERVER ROS_STATIC_PEERS
source tools/test_host/env.bash
M2 asm                          # 한 경로만 요청; 최종 결과까지 대기
```

M1은 `M1 asm`처럼 같은 방식입니다. `M2 stop`은 정지 요청, `M2 restart`는 정지 래치 해제만 수행합니다. 초기 위치가 맞아야 하며 `parked`는 실제 지정 위치·방향에 놓였을 때만 사용합니다. 개별 시험과 본 호스트 명령을 동시에 발행하지 않습니다.

이 작업은 PC 코드 동기화·AMR 통합·격리 통신 검증입니다. 실제 로봇 파일·서비스를 변경하거나 실물 주행 명령을 보내지 않았습니다. 따라서 현재 실행 중인 로봇에 `/M1/data`·`/M2/data` 서버가 준비됐다는 의미는 아닙니다.
