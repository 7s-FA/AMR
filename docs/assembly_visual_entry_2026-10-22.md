# 조립대 웨이포인트 시각 정렬 (2026-10-22)

M1·M2는 조립대 앞 웨이포인트 도착 후 마커로 계산한 진입 목표 방향을 먼저 맞춘다. 지도 경유점 좌표나 Nav2 경로를 변경한 작업이 아니다. 조립대 전용 `visual_entry_alignment: true`이며 자재창고·주차는 기본값 false로 기존 출력을 유지한다.

- 첫 전진 전 목표 방위각 오차가 6° 이내이고 각속도가 0.04 rad/s 이하가 되어야 한다. 오차가 20°를 넘으면 다시 전진을 멈추고 회전한다.
- 정렬 목표 거리를 22→30cm로 옮겨 기존 20cm 근접 보호보다 앞에서 정렬할 공간을 확보한다. 거리는 카메라–마커 광학 거리다.
- 전진 중 작은 회전 보정을 기존 최소 회전 속도 미만이라는 이유만으로 0으로 버리지 않는다. 기존 회전 상한·가속 제한은 유지한다.
- 방위각·방향·좌우 오차가 클수록 전진 속도를 줄여 정렬 시간을 확보한다. M1 최대 4.5cm/s, M2 최대 2.5cm/s와 기존 마지막 진입 속도를 유지한다.
- 사용자 요청에 따라 조립대 정렬 허용치를 좌우 ±5mm·각도 ±2°로 완화했다. 이 범위에서 정지 및 0.7초 유지 조건을 충족하면 마지막 진입으로 전환한다. 자재창고의 ±2mm·±0.7°는 유지한다.
- 정지 정렬과 길어진 최종 진입을 포함해 조립대의 1회 시간 제한을 45→55초로 조정했다. 모터·마커·odom 이상 정지, 20cm 근접 보호, 기존 엔코더 정지 목표를 유지한다.

실행 중인 현장 소스는 관제 저장소와 버전이 달라 각각의 현행 파일에 변경을 추가했다. M1 `common/runtime/docking_control.py`, `M1/config/docking.yaml`; M2 `B2/docking_control_b2.py`, `B2/config/docking.yaml`, `B2/make_docking_override.py`를 반영했다. 저장소 공통 제어에도 기본 비활성 옵션을 추가했다.

## 검증

실제 실행 소스 사본으로 보호·정렬 기준·다른 모드 출력 일치·완전 도킹 모의 검사 110개 통과. 기존 M2 제어 검사 21개, 저장소 공통 보호 검사 14개 통과. 완전 도킹 모의 검사는 좌우 ±6cm, 방향 ±12°, 영상 지연 120/300ms, 속도 양자화와 구동 응답 지연을 포함한 36개 사례다. 기존 제어도 이상적인 모델에서는 완료됐으므로 이 결과를 실물 성공률 향상 증거로 해석하지 않는다. 마커 보정 오차, 바닥 미끄러짐과 모터 정지마찰은 추가 실물 확인이 필요하다.

**현재 적용 상태:** 시각 진입 정렬·30cm 목표·55초 제한과 ±5mm·±2° 허용 오차를 M1·M2 모두 적용 확인했다. M1은 연결 복구 후 18:45 KST에 마지막 설정을 반영했으며, 로드된 코드·설정 해시, 카메라 수신, 제어권 idle, 직접 이동 명령 발행자 0을 확인했다. M1 마지막 변경 전 백업은 `backups/alignment-clearance-burger1-20261022-184517`이다.

현장 적용은 각 로봇 이동 비활성 및 제어권 idle을 확인한 뒤 도킹 대기 서비스만 갱신했다. 새 이동이나 주문 재시도는 요청하지 않았다. 로그·전후 소스·설정·모의 실행기·원격 백업 경로는 관제 작업공간 `.runtime/diagnostics/assembly-waypoint-alignment-20261022/`에 보관한다.
