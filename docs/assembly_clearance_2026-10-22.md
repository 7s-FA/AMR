# 조립대 정렬 전 근접 진입 보호 (2026-10-22)

M2 실패 기록에서 마커 4개를 모두 검출했음에도 약 15cm에서 보드 형상 검증이 실패했다. 정렬이 끝나지 않은 상태에서 근거리 목표를 계속 앞으로 당기는 제어가 남은 시야 공간을 소진했다.

M1·M2 조립대에만 `assembly_control.alignment_min_distance_m: 0.20`을 적용했다. 거리는 카메라에서 마커 보드까지의 광학 거리다. 기본값 0은 비활성화이며 자재창고와 주차 설정은 바꾸지 않았다.

정렬 전 전진 차단 기준은 최소 거리 + `align_speed_mps * (observation_timeout_s + 0.2) + 0.005`이다. 현재 M1은 약 23.65cm, M2는 약 22.25cm부터 여유 공간을 지킨다. 이 값은 영상 지연과 명령 지연·밀림을 고려한 소프트웨어 여유이며 실측 정지 거리 보장은 아니다.

- 보드 법선까지 좌우 오차가 허용 범위라면 전진 0으로 제자리 회전만 허용한다.
- 좌우 오차가 커 회전만으로 정렬할 수 없으면 `alignment_clearance_exhausted`로 정지한다. 이후 재접근 정책은 기존 mission 동작을 따른다.
- 좌우·각도·정지 조건과 기존 유지 시간을 충족한 뒤에만 최종 진입을 시작한다.
- 이미 확정된 최종 진입의 엔코더 정지 거리, 감속, 보호 조건은 유지한다.
- 마커 형상 검증 기준이나 정렬 허용치를 완화한 변경은 아니다. 도킹 성공률 자체는 추가 실물 확인이 필요하다.

## 검증 및 적용

두 로봇의 실제 실행 소스를 복사해 66개 보호·기록 재생·지연/밀림 모의 검사, 기존 M2 제어 검사 21개, 저장소 공통 제어 검사 12개 통과. 자재창고·주차의 기존/수정 코드 출력 일치를 비교했다.

17:55 KST에 양쪽 이동 작업 비활성, 모터 제어권 idle, 직접 이동 명령 발행자 0을 확인하고 도킹 대기 프로그램만 갱신했다. 로드된 파일 해시와 카메라 수신을 확인했다. 실제 이동은 요청하지 않았다.

현장 실행 파일은 저장소 소스와 버전이 다르므로 전체 파일 동기화 대신 각 현행 소스에 같은 보호만 추가했다. M1 현장 `common/runtime/docking_control.py`, `M1/config/docking.yaml`; M2 현장 `B2/docking_control_b2.py`, `B2/config/docking.yaml`, `B2/make_docking_override.py`에 반영했다.
